# Практические работы 3-4 по Django

Учебный проект по дисциплине «Структура программного обеспечения и базы данных».
Проект объединяет две практические работы: настройку авторизации пользователей в Django и работу с моделями, миграциями, административной панелью и ORM.

## Что реализовано

В рамках проекта создано приложение `accounts`, в котором настроены:

- главная страница проекта;
- регистрация пользователей;
- вход и выход из системы;
- защищенная страница профиля;
- административная панель Django;
- модели факультетов, курсов и профилей студентов;
- страница со списком курсов, данные для которой берутся из базы через ORM.

## Технологии

- Python 3.12;
- Django 6.1.1;
- SQLite;
- Django ORM;
- HTML и шаблоны Django.

## Запуск проекта

Склонировать репозиторий и перейти в папку проекта:

```bash
git clone <ссылка-на-репозиторий>
cd <папка-проекта>
```

Создать виртуальное окружение:

```bash
python -m venv .venv
```

Активировать окружение в Windows:

```bash
.venv\Scripts\activate
```

Установить зависимости:

```bash
pip install -r requirements.txt
```

Применить миграции:

```bash
python manage.py migrate
```

Создать администратора:

```bash
python manage.py createsuperuser
```

Запустить локальный сервер:

```bash
python manage.py runserver
```

После запуска сайт будет доступен по адресу:

```text
http://127.0.0.1:8000/
```

## Модели данных

В приложении `accounts` добавлены три основные модели:

- `Department` - факультет или направление подготовки;
- `Course` - учебный курс, связанный с факультетом;
- `StudentProfile` - профиль студента, связанный со стандартным пользователем Django.

Связи между сущностями:

- `Department` и `Course`: один факультет может иметь много курсов;
- `User` и `StudentProfile`: один пользователь имеет один профиль;
- `StudentProfile` и `Course`: студент может быть записан на несколько курсов.

## Примечание

Файл базы данных `db.sqlite3`, виртуальное окружение и локальные отчеты не входят в исходный код репозитория. После клонирования нужно применить миграции и создать собственного администратора.

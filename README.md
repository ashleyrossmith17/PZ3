# Django-проект для ПЗ 3 и ПЗ 4

Репозиторий содержит учебный Django-проект по дисциплине «Структура программного обеспечения и базы данных».
Проект сделан как продолжение двух практических работ: сначала была настроена авторизация пользователей, затем добавлены собственные модели, миграции, административная панель и запросы через Django ORM.

## Кратко о проекте

В проекте есть приложение `accounts`. Оно отвечает за пользовательские страницы, регистрацию, профиль и работу с учебными сущностями: факультетами, курсами и профилями студентов.

Основные возможности:

- регистрация нового пользователя;
- вход и выход из учетной записи;
- доступ к профилю только после авторизации;
- стандартная административная панель Django;
- модели с отношениями `OneToOneField`, `ForeignKey` и `ManyToManyField`;
- вывод списка курсов на отдельной странице;
- тесты для проверки авторизации и ORM-связей.

## Как запустить

Клонировать проект:

```bash
git clone https://github.com/ashleyrossmith17/PZ3.git
cd PZ3
```

Создать и активировать виртуальное окружение:

```bash
python -m venv .venv
.venv\Scripts\activate
```

Установить зависимости:

```bash
pip install -r requirements.txt
```

Подготовить базу данных:

```bash
python manage.py migrate
```

Создать пользователя администратора:

```bash
python manage.py createsuperuser
```

Запустить сервер разработки:

```bash
python manage.py runserver
```

После запуска проект открывается по адресу:

```text
http://127.0.0.1:8000/
```

## Модели приложения

В `accounts/models.py` описаны три модели:

- `Department` - факультет или направление;
- `Course` - курс, относящийся к факультету;
- `StudentProfile` - профиль студента, связанный с пользователем Django.

Связи между таблицами:

```text
User 1 : 1 StudentProfile
Department 1 : N Course
StudentProfile N : M Course
```

Для модели `Course` добавлено поле `description`, поэтому в проекте есть две миграции приложения `accounts`:

- `0001_initial.py` - создание основных моделей;
- `0002_course_description.py` - добавление описания курса.

## СРС 3 и СРС 4

СРС 3 реализует группы пользователей и контроль доступа. СРС 4 расширяет
существующий проект учебными группами и CRUD факультетов, групп и курсов.
Все списки, профиль и аналитика требуют входа. Новый пользователь получает
только группу `Student` и пустой `StudentProfile`. Переданные при регистрации
поля `groups`, `is_staff` и `is_superuser` не принимаются.

| Учётная запись | Роль | Возможности |
| --- | --- | --- |
| `spo_student` | `Student` | Просмотр списков, профиль, аналитика |
| `spo_methodist` | `Methodist` | Просмотр и CRUD всех трёх сущностей |
| `spo_staff` | `is_staff=True` | Вход в admin, без прав на модели |
| `spo_admin` | superuser и staff | Стандартный полный доступ admin |

`is_staff` открывает административный интерфейс, а разрешения Django определяют
доступ к моделям внутри него. Staff и superuser без группы `Methodist` получают
403 на пользовательских CRUD-маршрутах. Methodist без `is_staff` не входит в admin.
В шаблонах кнопки скрыты, но окончательная проверка всегда выполняется на сервере
для GET и POST. Анонимный посетитель перенаправляется на вход. Удаление выполняется
только POST с CSRF; GET открывает подтверждение. Остальные методы возвращают 405.

### Все страницы

| Маршрут | Назначение | Доступ |
| --- | --- | --- |
| `/` | Главная | Все |
| `/register/` | Регистрация Student | Все |
| `/accounts/login/` | Вход | Все |
| `/accounts/logout/` | Выход POST, возврат на главную | После входа |
| `/profile/` | Роли, факультет, учебная группа и курсы | После входа |
| `/departments/` | Факультеты и количество курсов и групп | После входа |
| `/groups/` | Учебные группы, факультеты и студенты | После входа |
| `/courses/` | Курсы, описание, факультеты и студенты | После входа |
| `/dashboard/` | ORM-аналитика с фильтром `?department=<pk>` | После входа |
| `/departments/add/`, `/groups/add/`, `/courses/add/` | Создание | Methodist |
| `/departments/<pk>/edit/`, `/groups/<pk>/edit/`, `/courses/<pk>/edit/` | Изменение | Methodist |
| `/departments/<pk>/delete/`, `/groups/<pk>/delete/`, `/courses/<pk>/delete/` | Подтверждение GET, удаление POST | Methodist |
| `/admin/` | Администрирование пользователей, групп и моделей | Staff + разрешения Django |

`Department` связан с `AcademicGroup` через ForeignKey с PROTECT;
`StudentProfile.academic_group` допускает NULL для прежних профилей и использует
PROTECT при наличии студента. Исходные `StudentProfile.department`, `courses`
и обратная связь `Course.students` сохранены. `Course.department` защищён PROTECT.
Удаление курса с записями студентов блокируется также сигналом ORM, включая
массовое удаление и admin. Связанные удаления возвращают понятное сообщение и 409.
Миграции `0001` и `0002` сохранены, изменения находятся только в `0003`.

В формах переиспользуется `StyledModelForm`, в представлениях `crud_views`,
в шаблонах `object_form.html`, `object_confirm_delete.html` и `object_actions.html`.
Курсы и группы используют `select_related('department')` и
`prefetch_related('students__user')`; профиль подгружает учебную группу, факультет
и курсы. Списки не выполняют отдельный SQL-запрос для каждой строки.
Аналитика считает записи по всем курсам; только диаграмма ограничена шестью.
Группировка популярности выполняется по `pk` и `title`, поэтому одноимённые
курсы разных факультетов не объединяются.

Проверка: `python manage.py check`, `python manage.py makemigrations --check --dry-run`,
`python manage.py test`. Прежние 8 тестов сохранены; дополнительные 11 проверяют
прямые GET/POST-запреты, роли, регистрацию, полный CRUD, права admin, защиту
связей, постоянное число ORM-запросов, динамические агрегаты и повторяемость seed.

В репозиторий не добавлены локальная база `db.sqlite3`, виртуальное окружение и файлы отчетов. Их нужно создавать или прикладывать отдельно, потому что они не относятся к исходному коду проекта.

## ПЗ 5: интерфейс Tabler

В пятой практической работе исходные страницы Django были перенесены на Tabler.
Библиотека сохранена локально в `static/vendor`, поэтому для запуска не требуется CDN.
Общая оболочка находится в `templates/base.html`; она используется всеми прежними
страницами авторизации, профиля и списка курсов. Навигация адаптируется под узкий
экран через кнопку меню Tabler.

## ПЗ 6: аналитика данных

Добавлен защищённый маршрут `/dashboard/`. Страница получает данные из существующих
моделей `Department`, `Course` и `StudentProfile` через Django ORM и строит три
диаграммы Chart.js:

- количество курсов по факультетам;
- количество профилей студентов по факультетам;
- популярность курсов по числу записей студентов.

Карточки показателей и контейнеры графиков вынесены в компоненты
`templates/accounts/components/`. Фильтр факультета передаётся как GET-параметр,
пересчитывает метрики и значения диаграмм на сервере. Данные передаются в JavaScript
без ручной подстановки через `json_script`.
